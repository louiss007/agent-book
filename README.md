# AI Agent 从原理到实践

## 构建能自主完成任务的智能体

{% hint style="info" %}
**核心观点**：Agent = 模型 + 工具 + 上下文 + 循环。模型提供智能，工程决定 Agent 是否可靠，产品设计决定它有没有价值。
{% endhint %}

AI 应用正在从“生成内容”走向“完成任务”。聊天机器人回答你的问题，Agent 则替你查资料、改代码、操作软件，并在过程中自己决定下一步做什么。这个转变带来的不只是更强的模型调用，而是一整套新的工程问题：如何设计工具，如何管理上下文，如何评测一个有多条可能路径的系统，如何在上线后防止它做错事。

本书试图把这些问题的原理讲透，并给出可以运行的代码。

## 这本书回答五个问题

| 问题 | 对应内容 |
|---|---|
| Agent 是什么？和聊天机器人、工作流有什么本质区别？ | 第一部分（第 1–4 章） |
| Agent 由哪些核心能力组成，各自的原理是什么？ | 第二部分（第 5–10 章） |
| 怎么从零开发一个 Agent，怎么选框架？ | 第三部分（第 11–16 章） |
| 怎么把 Agent 做到可靠、安全、可上线？ | 第四部分（第 17–19 章） |
| Agent 会往哪里发展，产品应该怎么设计？ | 第四、五部分（第 19–21 章） |

本书不追求覆盖所有框架和产品，也不做没有依据的排行榜。每一章只回答一个问题：**为什么需要它，它的代价是什么，什么场景下值得用。**

## 贯穿全书的项目：Atlas 研究助手

本书不提供互不相干的代码片段。所有实战代码都围绕一个逐步演进的示例项目 **Atlas 研究助手**：

- 第 4 章：一个最小可运行的工具调用循环
- 第 5–9 章：加入搜索、网页读取、代码执行、规划、记忆、RAG 与上下文管理
- 第 10 章：拆分为“检索员 + 分析员 + 撰稿人”的多 Agent 协作
- 第 12 章：整合为一个可用的命令行应用
- 第 15–18 章：补上评测、追踪、安全护栏与部署

Atlas 的接口在首次定义后保持稳定，后续章节只做增量扩展。这既是为了让代码可以逐章运行，也是为了演示一个真实的工程约束：**Agent 系统会不断加能力，但核心抽象必须稳。**

项目总览见 [Atlas 项目总览与演进路线](atlas/overview.md)，接口定义见 [Atlas 接口清单](atlas/interfaces.md)。

## 代码与环境

- Python 3.11 及以上
- 模型通过 **OpenAI 兼容接口**接入，可替换为任意兼容服务
- 所有示例提供**离线模式**：使用 Mock LLM 与本地语料，不需要 API Key 即可跑通主流程
- 需要联网的工具（搜索、网页读取）在离线模式下使用固定样本
- 代码以“能读懂、能改动、能验证”为标准，不以生产级完整性为目标；生产化改造在第 17–18 章展开

{% hint style="warning" %}
Agent 领域的产品功能、框架 API 与基准分数变化很快。书中涉及具体版本的内容会标注“截至写作时”，实际使用时请以官方文档为准。
{% endhint %}

## 阅读约定

- 专业术语首次出现时附英文原文，全书以[附录 A 术语表](appendix/a-glossary.md)为准
- 代码块均标注语言；架构与流程一律使用 Mermaid 图，不依赖外部图片
- 每章包含“常见误区”，它们来自真实项目中的失败经验，而不是理论上的极端情况
- 每章末尾的“思考与练习”至少包含一道动手题，建议对照 Atlas 仓库完成

## 本书不做什么

- 不是 Prompt 模板合集：提示词技巧会讲，但重点在系统设计
- 不是框架说明书：框架只讲设计取舍与选型依据，不逐行讲 API
- 不是论文综述：关键论文会引用并说明其工程意义，但不追求穷尽
- 不承诺“全自动”：多数有价值的生产系统仍然是“Agent 自主 + 人在关键点把关”
